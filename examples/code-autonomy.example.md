## Directory Semantics

The repo is organized by:
- **app/** — application name (e.g., payments, auth, gateway)
- **env/** — environment (dev, staging, prod)
- **region/** — deployment region (us-east-1, eu-west-1)

Example: `apps/payments/envs/prod/us-east-1/values.yaml`

## Coding Conventions

- Language version: Python 3.11 / Java 17 / Node 20
- Formatting: black + isort / Prettier / google-java-format
- Linting: ruff / ESLint / Checkstyle
- Naming: snake_case for Python, camelCase for Java/JS
- All public functions must have docstrings / JSDoc / Javadoc
- No wildcard imports

## Testing

- Framework: pytest / JUnit 5 / Jest
- Run tests: `pytest tests/` / `./mvnw test` / `npm test`
- Test files mirror source: `src/services/auth.py` → `tests/services/test_auth.py`
- Minimum coverage target: 80%
- Integration tests are in `tests/integration/` and require Docker

## Architecture Notes

- API layer → Service layer → Repository layer (no skipping layers)
- Database access only through repository classes
- All external API calls go through `src/services/external/` with retry + circuit breaker
- Configuration loaded from environment variables via `src/config.py`
- Background jobs use Celery / Spring Batch / Bull queues

## Important Files

| File | Purpose |

## Domain Context

<!-- Help the agent understand business-specific terminology -->

- **Tenant** — an organization that uses our platform
- **Workspace** — a project space within a tenant
- **Pipeline** — a sequence of automated processing steps
- Tenants can have multiple workspaces; each workspace has its own pipelines

## Things to Watch Out For

- Never modify files under `generated/` — they are auto-generated by protobuf
- The `legacy/` directory is deprecated; redirect callers to new implementations
- Database migrations must be backward-compatible (zero-downtime deploys)
- Environment variables prefixed with `INTERNAL_` must not be logged
